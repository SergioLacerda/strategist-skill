# ADR-0025 — Generated Documentation and AI-First Anti-Drift

**Title:** Generated Documentation and AI-First Anti-Drift
**Status:** Accepted
**Date:** 2026-08-11
**Mission ID:** 20260811-documentacao-gerada

## Context

Strategist should separate documentation written by humans (decisions, trade-offs, principles, usage, examples, limitations) from inventories that a machine should keep current by construction. The proposed inventory set is `docs/generated/{command-tree,package-map,schema-index,contract-index,event-catalog,eval-scenarios,coverage-policy,quality-budgets}.md`, with a single `make docs-generate` entry point and a CI gate that fails on drift (`git diff --exit-code docs/generated/`). Every generated file carries uniform provenance metadata (`generated`, `source`, generator version, and `do not edit manually`).

Repository inspection found that `docs/generated/` and `make docs-generate` do not exist. Strategist already practices most of the underlying principle — determinism plus a failing gate — in dispersed form: a real generated-content-with-provenance pattern (`internal/compile/agent_awareness.go`, using an HTML-comment marker `<!-- generated by: strategist compile — do not edit manually -->`), and several working anti-drift gates implemented as ad hoc shell scripts (`scripts/check-contract-consistency.sh`, `scripts/check-convergence.sh`, `scripts/check-docs-governance.sh`, `scripts/check-quality-budgets.sh` + `quality-budgets.tsv`, `scripts/check-coverage-gate.sh` + `coverage-packages.tsv`). The actual gap is form and navigability — a consolidated, human- and agent-readable markdown inventory — not the absence of determinism or gating.

Two alternatives were considered:

- **Leave the dispersed mechanisms as-is** and not introduce `docs/generated/`. Rejected: the base document's explicit goal (a single navigable inventory, e.g. `contract-index.md` showing contract/origin/implementation/tests/telemetry/lifecycle in one place) is not met by scattered scripts and TSVs, even though the underlying gating works.
- **Replace all existing TSVs and check scripts outright** with the new `docs/generated/*.md` files in one pass. Rejected for this decision: `legacy_compatibility: required` is the default mission constraint, and no explicit instruction authorized removing `quality-budgets.tsv`, `coverage-packages.tsv`, or the existing `check-*.sh` gates; whether they are replaced, kept as the source feeding a generated view, or left untouched is deferred to implementation time (UNC-02), not settled by this ADR.

## Decision

Adopt the following design:

1. Introduce `docs/generated/` as the canonical directory for inventories reconstructible from existing deterministic sources (Cobra command tree, `.strategist/schemas/*.yaml`, `internal/telemetry/schema.go` attribute constants, `go list`, existing TSVs).
2. Introduce a single entry point (`make docs-generate`) and a diff-based anti-drift gate, following the same `*-gate` pattern already used in `make/governance.mk`.
3. Standardize the provenance metadata block across all generated files, reusing the HTML-comment pattern already in production in `agent_awareness.go`, rather than inventing a new format.
4. Evolve `scripts/check-contract-consistency.sh` and `scripts/check-convergence.sh` toward the new generated inventories instead of discarding them outright.
5. Treat the relationship between `quality-budgets.tsv`/`coverage-packages.tsv` and the new `docs/generated/{quality-budgets,coverage-policy}.md` (task 6 / SQ-002) as an accepted side quest for this mission, without prejudging substitution vs. derivation.
6. Defer the exact generation mechanism (shell scripts vs. a new Go command) and the CI-vs-local-vs-both placement of the diff gate to implementation time — recorded as open questions (UNC-01, UNC-03) in the refined package, not settled by this ADR.

This is an analysis/documentation decision only. No code, script, or CI configuration was written or modified by Strategist as part of this mission; implementation of items 1–5 above is out of Strategist's execution scope (`task_type: implementation_handoff`) and requires a separate coding task.

## Consequences

**Positive:**
- A single navigable `docs/generated/` directory replaces the need to know which of five different scripts/TSVs documents a given fact (contracts, events, schemas, commands, budgets).
- Reusing the existing `agent_awareness.go` provenance pattern avoids inventing a second, competing "generated content" convention.
- Evolving `check-contract-consistency.sh`/`check-convergence.sh` instead of discarding them preserves working anti-drift coverage during the transition.
- `event-catalog.md` (task 5) creates a natural documentation surface for the `EventSink`/event envelope work already refined under the pluggable-governance item (`20260811-governanca-plugavel`), without introducing a second source of truth for event names.

**Negative / follow-up required:**
- Four open design questions (UNC-01: script vs. Go generator; UNC-02: TSV substitution vs. derivation vs. out-of-scope; UNC-03: CI vs. local vs. both gate; UNC-04 default recommendation only) are not fully resolved by this ADR and must be closed before implementation tasks can be written precisely.
- `eval-scenarios.md`'s deterministic source was not identified during discovery (task 7.1) and needs further investigation before that specific generator can be scoped.
- Consolidating five heterogeneous gate scripts into one `docs/generated/` diff gate risks a period where both old and new gates run in parallel, or a regression if the consolidation drops a check the old scripts covered.
- No CI workflow references `docs/generated/` today; adding one (if UNC-03 resolves toward CI) is itself a CI-configuration change requiring separate review.
