# ADR-0015 — ADR index by theme instead of physical subfolders

**Status:** Accepted  
**Date:** 2026-08-04  
**Context:** `20260804-adr-canonical-migration`

---

## Context

ADRs generated by Strategist missions in this repository were being written to the
runtime fallback path (`.analysis/archived/*-adr.md`) instead of the canonical
`docs/adr/` directory, because `.strategist/active.yaml#adr.canonical_path` was unset
(config drift — the field had been set once, in mission `20260728-adr-canonical-docs`,
but was lost, and the installer's `active.yaml` template generator has no support for
seeding it). Fixing that raised a second question from the same request: with 14
existing ADRs (0001–0014) and growing, should they be sub-organized into thematic
subfolders (`docs/adr/<theme>/NNNN-slug.md`) to speed up lookup?

## Decision

Do not move ADRs into physical subfolders. Instead, maintain a themed index table in
`docs/adr/README.md` that groups existing ADRs by topic without relocating any file.

Rejected alternative — physical subfolders per theme: at the volume evaluated (14
items), this would break at least 8 known hardcoded cross-references to specific
`docs/adr/NNNN-*.md` paths across `docs/`, `internal/telemetry/`, and
`internal/domain/` test files, and would require redesigning the existing flat
filename-numbering scan (`contracts/narrative/07-adr.md` § Canonical Destination
Resolution) to decide between a global sequence and a per-theme sequence — a real
design cost not justified by the lookup problem it would solve.

Rejected alternative — per-ADR `theme:` frontmatter tag with a generated index: viable,
but adds a maintenance mechanism (keeping frontmatter and the generated table in sync)
that a hand-maintained table does not need at this volume. Left as the natural next step
if the index in `docs/adr/README.md` becomes hard to keep current by hand.

## Consequences

- `docs/adr/` stays flat; the existing numbering scan contract needs no change.
- All known hardcoded references to specific ADR paths remain valid.
- `docs/adr/README.md` must be updated by hand (or by a future Sniper documentation
  task) whenever a new ADR is added — this is a manual step, not automated by this
  decision.
- If the ADR count grows large enough that the themed table itself becomes hard to
  scan, this decision should be revisited — no fixed numeric threshold is set here;
  the trigger is the index ceasing to serve its purpose in practice, not a count.
