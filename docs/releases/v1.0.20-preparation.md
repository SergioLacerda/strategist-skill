### Published artifact verification

GoReleaser is configured to produce six platform/architecture binaries,
`SHA256SUMS`, and release assets named `strategist-<os>-<arch>`. After
publication, verify separately:

- [ ] The tag is exactly `v1.0.20` and points to the verified release commit.
- [ ] No GitHub Release already exists for `v1.0.20` before workflow start.
- [ ] Every expected binary and `SHA256SUMS` asset is present and non-empty.
- [ ] Cosign bundles exist for every published binary/checksum asset.
- [ ] SBOM and GitHub build-provenance attestation are present.
- [ ] `make check-release-assets TAG=v1.0.20` passes against the published
      release.
- [ ] Download, checksum, signature, and installation verification succeeds on
      the supported platform matrix.

Local snapshot files prove build output only. They do not prove GitHub asset
publication, signature availability, SBOM upload, or attestation completion.

## Tooling and environment notes

- Release verification depends on the Go version declared by `go.mod`, network
  access for dependency/tool downloads, and enough writable temporary disk for
  Go build and GoReleaser caches.
- The final candidate must be checked from a clean checkout after the single
  release-preparation commit; do not treat the current dirty worktree as final
  release evidence.
- If a gate fails because of cache or disk quota, preserve the failure output,
  clean only the relevant cache with explicit approval, and rerun from the
  same clean candidate.

## Rollback and stop conditions

Stop before tagging or publishing when any of these occurs:

- the selected release commit is dirty, ambiguous, or differs from the
  reviewed inventory;
- the `v1.0.20` tag already exists or a GitHub Release already exists;
- release verification, generated documentation, embedded catalog, or lock
  checks report drift;
- GoReleaser artifacts are missing, duplicated, or have unexpected names;
- checksum, Cosign, SBOM, attestation, or published-asset verification fails.

Rollback target: keep `v1.0.19` as the last-known-good published boundary. Do
not move or delete it. Preserve failed snapshot/release evidence for diagnosis
and rerun only from a corrected, independently verified commit.
