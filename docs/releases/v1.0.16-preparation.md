## Rollback and stop conditions

Stop before tagging or publishing when any of these occurs:

- the selected release commit is dirty, ambiguous, or differs from the reviewed
  inventory;
- `v1.0.16` already has a tag or GitHub Release;
- release verification, generated documentation, embedded catalog, or lock
  checks report drift;
- GoReleaser artifacts are missing, duplicated, or have unexpected names;
- checksum, Cosign, SBOM, attestation, or published-asset verification fails.

Rollback target: keep `v1.0.15` as the last-known-good published boundary. Do not
move or delete it. Preserve failed snapshot/release evidence for diagnosis and
rerun only from a corrected, independently verified commit.
